## Что делаем

Три экрана поверх `planTrip()` из `src/core`. Пользователь — **водитель грузовика, телефон, портрет, смотрит на экран 3 секунды на парковке**. Отсюда: крупный текст, один ответ на экран, никаких сравнений вариантов.

Карта — НЕ в этой фазе (см. `NOT_NOW.md`). Маршрут показываем лентой времени.

## Критерий «работает»

Приложение запускается в Expo Go (`npx expo start`), MSW включён в dev-режиме через `src/core/mocks/native`, и:
1. На экране 1 вводишь адреса-заглушки (координаты пресетов, геокодинга нет — `NOT_NOW.md`), нажимаешь «Построить».
2. Экран 2 показывает четыре стадии по очереди.
3. Экран 3 показывает ленту с 2 остановками и ETA из `PlanResult`.
4. Переключение мок-сценария на «все парковки заняты» (кнопка на экране 1, только в `__DEV__`) → экран 3 показывает состояние конфликта.
5. `npm test` зелёный: тесты фазы 1 не тронуты + тесты экранов через `@testing-library/react-native`, где `planTrip` ходит через MSW (не jest.mock).

## Стек (не расширять)

Expo Router для навигации, `@testing-library/react-native` для тестов экранов. Стилей-библиотек не ставить: `StyleSheet` из `react-native`, токены в одном файле `src/ui/theme.ts`.

## Экраны

### Экран 1 — Ввод (`src/app/index.tsx`)
- Откуда / Куда: выбор из 3–4 пресетов (города Польши/Германии с координатами, констант-файл `src/ui/presets.ts`). Текстового поля с геокодингом нет.
- Время выезда: по умолчанию «сейчас», можно сдвинуть на +30 мин / +1 ч / +2 ч.
- Вес авто: пресет «Фура 40 т», редактируемое число.
- Одна большая кнопка «Построить маршрут».
- В `__DEV__`: маленький переключатель «Мок: все парковки заняты» — пробрасывается в `planTrip` через параметр или заголовок, как описано в `API_CONTRACT.md`.

### Экран 2 — Расчёт (`src/app/planning.tsx`)
Не спиннер. Четыре строки, загораются по очереди:
1. Маршрут построен
2. Остановки расставлены
3. Парковки проверены
4. Расписание собрано

`[предположение]` `planTrip` из фазы 1 может не отдавать прогресс. Тогда: сначала спроси пользователя, стоит ли добавить в контракт `onProgress`-колбэк (одна строка в ядре), либо показывай стадии по таймеру — второе честно пометь как имитацию в `DECISIONS.md`.

### Экран 3 — Результат (`src/app/result.tsx`)

**Верхняя карточка-ответ** (главное на экране, самый крупный текст):
- `status: 'ok'` → «Прибытие 15:42 · Вождение 8:10 · 2 перерыва · По норме»
- `status: 'conflict'` → красная карточка: текст из `conflict.reason`, ниже — `nearestFreeParking` если есть, и две кнопки: «Выехать раньше» (возврат на экран 1 с временем −30 мин) и «Другая парковка» (пока `NOT_NOW.md`: показать тост «скоро»).

**Лента** (вертикальный список):
- Старт: время, название пресета
- Между остановками: «↓ 4 ч 25 мин вождения»
- Остановка: время приезда, название парковки, «перерыв 45 мин», «свободно N из M на HH:MM», индикатор `confidence` (одно слово: «сейчас» / «прогноз»)
- Финиш: время, название

Все данные — из `PlanResult`, ничего не вычислять на экране. Если поле нужно, а в контракте его нет — спросить.

## Шаги

1. Expo Router + тема + пресеты. Пустые три экрана с навигацией. Проверка: `npx expo start`, переходы работают. Скриншот или описание того, что видно.
2. Включить MSW в dev по `API_CONTRACT.md` (раздел «Как включить моки»). Проверка: в консоли Metro видно перехваченный запрос.
3. Экран 1 + вызов `planTrip` → переход на экран 2. Тест: нажатие кнопки вызывает `planTrip` с координатами пресетов (проверяем через MSW, что ушёл запрос к TomTom с этими координатами).
4. Экран 2.
5. Экран 3, состояние `ok`. Тест: рендер с фикстурой `PlanResult` из `API_CONTRACT.md` показывает ETA и 2 остановки.
6. Экран 3, состояние `conflict` + dev-переключатель. Тест на красную карточку.
7. Отчёт в `STATE.md`.
